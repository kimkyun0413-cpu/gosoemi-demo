## 이번 코드 변경

- `ai_runtime.py`: 기능별 출력 상한과 추론 수준, 사용량 추출, 공개 준비 검사, 서버 전용 사용량 RPC 클라이언트.
- 글 생성: 실제 응답의 입력·출력·추론·전체 토큰을 읽는다. 없는 값은 0원이 아니라 `null`(모름)이다.
  전체 토큰에 추론을 다시 더하지 않는다. 본문·녹음·키는 사용량 로그나 DB에 넣지 않는다.
- 고소장과 표현 바꾸기는 최대 8,192 출력 토큰, 글 채팅 2,048, 음성 답변 1,024 등으로 나눈다.
  토큰 상한으로 끊긴 응답은 완성된 초안처럼 반환하지 않는다. 실제 품질과 길이는 유료 시험에서 조정해야 한다.
- 기본 글 모델은 실제 코드와 같은 `gemini-3.5-flash-lite`; `GEMINI_MODEL`로 설정할 수 있다.
  이전 대화에서 비교한 3.8 Flash의 가정 비용을 현재 앱의 고소장 비용으로 사용하지 않는다.
- 일반 이용자 AI는 `AI_PUBLIC_LAUNCH_ENABLED=true`와 공개 준비 조건을 모두 충족해야 열린다.
  관리자 시험은 별도로 가능하지만 `AI_FEATURES_PAUSED=true`가 항상 우선한다.
  공개 조건: 유료 등급 확인 표시, 적합한 호스팅 확인 표시, 18세 적용, v3 시행, DB 사용량 관리 활성화.
  확인 표시 자체가 Google 결제 상태나 법률 적합성을 자동 검증하는 것은 아니다. 콘솔/문서 검증 후에만 설정한다.
- 사용량 DB: 서버에서 검증한 사용자 ID로 예약한 뒤에만 AI를 호출한다. 계정별/전체, 시간별/24시간별 상한을
  같은 DB 트랜잭션에서 검사한다. 서버 재시작·여러 앱 인스턴스가 같은 DB를 사용해도 기록은 유지된다.
  DB 오류 때 메모리 제한으로 우회하지 않는다. 실패 요청도 호출 상한에는 남는다(청구 여부와 다름).
- 사용량 완료 기록에 실패해도 만든 답변은 보존한다. 예약이 계속 한도에 포함되고 운영 로그에 오류 종류만 남는다.
  사용량이 미확인인 요청을 무료였다고 계산하지 않는다.
- 본인 사용량은 기존 자료 ZIP에 추가되며, 탈퇴 시 FK로 삭제된다. 30일 지난 기록은 매일 정리하는 작업을 설정해야 한다.
- 초안 동시 저장: 기존 읽기→upsert 사이의 경쟁을 발견했다. 새 `save_case_draft_checked` RPC는 버전 비교와 저장을
  한 DB 연산에서 처리한다. `DRAFT_ATOMIC_SAVE_ENABLED`는 SQL 적용 후에만 켠다.
  기존 단독 초안 화면의 명시적 덮어쓰기 동작은 유지하며, 작업 공간의 expected timestamp 검사를 원자적으로 바꾼다.

## 서버 이전 준비

> 2026-10-14 통합: 서버 파일은 서버 이전 준비(main `e9b9c33`)와 합쳤습니다. 파일 목록·시험 배포·전환 목록·되돌리기의 최신본은 [server-migration-plan.md](server-migration-plan.md)입니다.

Dockerfile, TLS 프록시(Caddy), compose 파일, 값이 비어 있는 `.env.example`을 준비했다.
새 서버 생성·도메인 구매·DNS·결제·OAuth 관리 화면은 이번 작업에서 변경하지 않았다.

1. 서버 후보를 비용/관리 책임과 함께 선택한다. 1GB는 **시험 후보**이며 이용자 300명의 동시 사용을 보장하지 않는다.
   Lightsail은 보안 업데이트·운영 감시 책임이 운영자에게 있고, 관리형 호스팅은 그 부담을 줄이는 대신 요금이 다르다.
2. 구입 전 약관·개인정보 처리 계약/국가를 확인한다. 새 서버는 가상 사건만으로 먼저 시험한다.
3. 기존 설정을 서버 `.env`에 옮긴다. `chmod 600 .env`; AI 멈춤·이메일 가입 중단·판매 off 유지.
   `.env.example`을 그대로 사용하면 실제 로그인 설정이 없는 상태다. 기존 공급자 설정을 보존해야 한다.
4. `docker compose --env-file .env -f deploy/compose.yaml up -d --build`
   80/443만 공개하고 8501은 프록시 내부에서만 접근한다. 인증서, 마이크(HTTPS), WebSocket 연결을 확인한다.
5. APP_BASE_URL, Google redirect, Supabase Site URL/허용 Redirect URLs, 네이버 개발자 Callback URL,
   **naver-auth Edge Function의 반환 주소 설정**을 한 목록으로 대조한다. 도메인만 바꾸면 로그인이 자동으로 유지되는 것은 아니다.
6. 같은 Supabase 프로젝트를 계속 쓰므로 계정/사건/증거를 복사하지 않는다. 주소가 바뀌어 첫 재로그인은 필요할 수 있다.
7. 새 서버에서 Google·네이버 로그인, 새로고침·로그아웃, 사건 저장·내려받기, iPhone 마이크/음성/키보드,
   실제 메모리·동시 요청을 확인한다. 이전 주소는 전환 안내와 제한된 되돌리기 용도로 유지한다.

운영 이미지는 수정 없이 새 이미지로 교체한다. 파일 감시를 끈 상태에서 실행해 배포 중 hot-reload 문제를 줄인다.
Docker 이미지는 비밀값·실제 사용자 JSON·ZIP을 포함하지 않는다. Docker 빌드 및 실제 TLS 배포는 별도 확인이 필요하다.

## AI 다시 켜는 순서

1. 결제 보류를 운영자가 해제하기 전에는 결제 연결·충전·자동 충전을 진행하지 않는다.
2. 적용할 프로젝트/키의 유료 등급을 콘솔에서 확인한다. 월 지출 상한과 알림은 별도 설정한다.
   Google 프로젝트 지출 상한은 처리 지연에 따른 초과가 가능하다. 앱 호출 상한은 **원화 고정 상한이 아니다**.
3. 서버/방침/18세 적용과 DB 변경을 시험 환경에서 검증한다. 날짜를 임의로 정해 운영 동의를 바꾸지 않는다.
4. 처음에는 관리자만 가상 사건을 시험한다. 한 건 생성, 이어지는 채팅, 음성 사용량을 실측한다.
5. 초안 품질: 사실 추가/누락, 날짜·금액, 모르는 상대방, 민사/형사 안내, 제출 문서 형식, 실패 후 자료 유지 확인.
   자동 테스트 통과와 법률적 정확성 검증은 다르다.
6. 실제 개인 사건은 개인정보 처리 조건과 서버가 정리된 뒤 시험한다. 모든 이용자 공개는 준비 검사 후에만 한다.

## 2026-10-14 검토 → 채택·구현: 사용량 기록의 서버 키 최소화 (Claude, 운영 미적용)

**비교**
| 방법 | 이용자 조작 | 서버 키가 새면 | 추가 작업 |
|---|---|---|---|
| A. 원안: service_role 키 | 불가 | **전체 자료 노출** | 없음 |
| B. 이용자 토큰으로 예약·완료 | 완료 값(토큰 수)을 본인 것은 꾸밀 수 있고, 예약을 반복해 **전체 한도를 소진**(다른 이용자 AI 차단) 가능 | — | 적음 |

| **D. 전용 DB 로그인 역할(추천)** | **불가** | **예약·완료 두 함수만 가능**(어떤 표도 못 읽음) | DB 연결 드라이버, 역할 비밀번호 관리 |

**채택한 D — 마이그레이션 `20261014000000_ai_usage.sql`에 바로 반영(별도 수정안 폴더는 없앰)**
