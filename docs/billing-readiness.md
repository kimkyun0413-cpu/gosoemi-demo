# 결제 기능 준비 상태

작성 2026-10-06. **실제 결제는 할 수 없습니다.** 결제사를 정하지 않았고, 사업자 정보와 결제사 계약이 없습니다.

## 1. 확인한 현재 상태
- 기존 결제 코드·결제사 설정·결제 관련 DB 표: 없음
- 사업자 정보: 개인정보처리방침에 "개인이 운영하는 서비스(사업자등록 전)"로 표시되어 있음
- 결제사 테스트 키: 없음 → 결제사 연동 시험은 하지 못했고, 가짜 결제사(mock)로만 시험함

## 2. 판매 전에 갖춰야 할 것
| 항목 | 근거·이유 |
|---|---|
| 사업자등록 | 결제사 가맹 계약과 판매자 정보 표시에 필요 |
| 통신판매업 신고 | 전자상거래법 제12조 제1항(거래 횟수·규모가 공정거래위원회 고시 기준 이하면 예외) |
| 결제사 선택·계약, 테스트 키 발급 | 결제사마다 서명 검증·승인 확인 방식이 달라 어댑터를 새로 써야 함 |
| 환불·청약철회 규정 | 전자상거래법 제17조: 원칙 7일 이내 청약철회. 디지털콘텐츠 제공이 시작되면 제한될 수 있으나(제2항 제5호), 그 사실을 표시하고 시험 사용 등 조치를 해야 함(제6항) |
| 결제 기록 5년 보존 | 전자상거래법 시행령 제6조 제1항 제3호(대금결제 기록 5년). 동의를 철회한 소비자 기록은 별도 보존(제2항 제3호) |
| 이용약관·개인정보처리방침 개정 | 결제 정보 항목, 결제사 위탁, 결제 기록 보존 기간 추가 |

## 3. 준비한 구조 (모두 미적용·미배포)
- [billing.py](../billing.py): 요금제 설정 읽기와 표시 규칙. 판매 조건 전에는 가격·결제 버튼을 보이지 않음. 앱의 '계정 및 개인정보 메뉴'에는 "유료 요금제는 준비 중, 결제를 요청하지 않음"만 표시
- [DB 제안](../supabase/proposals/billing/20261007000000_billing.sql) / [되돌리기](../supabase/proposals/billing/20261007000000_billing_rollback.sql)
  - 금액은 서버 표(`billing_plans`)에서만 정함. 클라이언트가 보낸 금액은 쓰지 않음
  - 주문 생성 `billing_create_order(요금제, 멱등키)`: 같은 키로 두 번 눌러도 주문 1건
  - 결과 반영 `billing_apply_event(...)`: 결제사 서버 확인을 마친 Edge Function(service_role)만 호출. 같은 이벤트 재수신 무시, 금액 불일치 거부, 이미 처리된 주문 무시
  - 성공 → 이용권 기간 부여 / 실패·취소 → 이용권 없음 / 환불 → 이용권 즉시 종료
  - 정기결제: 갱신 실패 → `past_due`(받은 기간까지는 이용 가능), 해지 → 기간 끝까지 이용 후 갱신 안 함, 만료 → 이용권 종료
  - 탈퇴 시 `billing_retain_orders_for_user()`로 결제·환불 기록을 비공개 영역에 5년 보존 후 계정 삭제
- [결제 결과 수신 Edge Function 초안](../supabase/proposals/billing/functions/billing-webhook/): 결제사 서명 검증 → 결제사 API 재확인(어댑터) → DB 반영. 지금은 시험용 mock 어댑터만 있음

## 4. 시험 결과
- DB 제안: 로컬 임시 Postgres에서 30/30 통과 (`supabase/tests/local_billing_test.py`)
- Edge Function: Deno 테스트 8/8 통과, 타입 검사 통과 (`handler_test.ts`)
- 앱 표시 규칙: 단위 테스트 6개 통과 (`tests/test_billing.py`)
- **결제사 실제 API, 결제 화면, 웹훅 수신은 시험하지 않음**(결제사·키 없음)

## 5. 설정 예시 (값은 예시이며 실제 가격 아님)
```toml
# Streamlit Secrets
BILLING_MODE = "off"        # off | test | live. live여도 결제사 연동 전에는 판매하지 않음
BILLING_PLANS_JSON = '[{"plan_id":"basic","name":"(미정)","kind":"one_time","amount":1000,"period_days":30}]'
```
Edge Function Secrets(결제사 결정 후): `BILLING_MODE`, `BILLING_PROVIDER`, `BILLING_WEBHOOK_SECRET`. 비밀값은 코드·문서에 적지 않습니다.

## 6. 결제사 결정 후 남은 개발
1. 결제사 어댑터 작성(서명 검증, 승인/조회 API로 금액·상태 재확인, 이벤트 형식 변환)
2. 결제 시작 화면: `billing_create_order` 호출 → 결제사 결제창 → 돌아오면 "확인 중" 표시 후 서버 반영 결과만 신뢰
3. 기능 제한 지점에서 `billing_has_entitlement` 사용
4. 탈퇴 Edge Function에 결제 기록 보존 단계 추가(현재 배포본 수정 필요)
5. 결제사 테스트 키로 성공·실패·취소·환불·중복 전송·갱신 실패 시험

## 7. 환불·해지 안내 초안 (빈칸은 확정 후 채움)
- 결제 후 [ ]일 이내, 유료 기능을 사용하지 않은 경우 전액 환불합니다. (전자상거래법 제17조 제1항 기준 7일 이상)
- 유료 기능 이용을 시작한 뒤의 환불: [ 확정 필요 — 제17조 제2항 제5호·제6항 요건 검토 ]
- 정기결제 해지: 언제든 해지할 수 있고, 이미 결제한 기간이 끝날 때까지 이용할 수 있습니다. 다음 결제일부터 청구되지 않습니다.
- 갱신 결제 실패: [ ]일 동안 결제 수단을 바꿀 수 있도록 안내하고, 그 뒤 이용권이 끝납니다.
- 환불 신청: [ 문의 이메일 ] / 처리 기한 [ ]일
- 운영 절차: 환불 요청 접수 → 결제사 관리 화면에서 환불 → 웹훅으로 `refunded` 반영 확인 → 이용자에게 회신. 분쟁 기록은 3년 보존(시행령 제6조 제1항 제4호)
