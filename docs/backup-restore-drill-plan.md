# 백업·복구 연습 계획 (별도 무료 프로젝트) — 2026-10-12 준비, 실행 전

운영 자료를 복사하기 **전에** 정해 두는 계획입니다. 운영자가 승인하기 전에는 운영 DB를 백업하지 않습니다.
스크립트는 로컬 임시 DB에서 실제로 왕복 시험을 마쳤습니다(`supabase/tests/local_backup_restore_test.py`, 17/17).

## 1. 대상
| 무엇 | 범위 | 도구 |
|---|---|---|
| DB 구조 | `public`, `naver_private` 스키마의 표·함수·트리거·정책·권한 | `scripts/backup_supabase.sh` |
| DB 자료 | `public.*`(사건·초안·사건 정리·동의 기록 등), `naver_private.*`(네이버 연결), `auth.users`, `auth.identities`(로그인 계정) | 같은 스크립트 |
| 증거파일 | Storage `case-evidence` 버킷의 파일 | `scripts/backup_storage.py backup` |
| 넣지 않는 것 | Supabase가 관리하는 나머지 스키마, `storage.objects` 목록(파일을 올리면 다시 생김), 인증 로그 | — |

- 담기는 개인정보: 회원 이메일, 로그인 방법, 사건 내용(제3자 정보 포함 가능), 초안, 동의 기록, 증거파일. **운영 DB 비밀번호·secret 키는 백업에 들어가지 않습니다.**

## 2. 연습용 프로젝트
- 운영과 같은 조직('고소미')에 **새 Free 프로젝트** 1개(Free는 조직당 2개까지 — 지금 1개 사용). 이름 예: `gosomi-restore-test`, 지역: 서울(운영과 같게).
- 앱(Streamlit)과 연결하지 않습니다. 로그인 공급자(네이버·Google)도 켜지 않습니다. 새 가입 끄기.
- 연습이 끝나면 **같은 날 프로젝트를 삭제**합니다(Settings → General → Delete project).

## 3. 보관 위치
- 이 Mac의 `~/gosoemi-backups/`만 사용(스크립트 기본값, 폴더 권한 700·파일 600). **FileVault 켜짐 확인(2026-10-12).**
- iCloud·Google Drive 등 동기화 폴더, 메일·메신저, 저장소(git)에 올리지 않습니다.
- 복구 중 풀린 파일은 스크립트가 임시 폴더에 두고 끝나면 지웁니다(`mktemp` + `trap`).

## 4. 암호 관리
- 백업 파일은 AES-256으로 암호화합니다. 암호는 **운영자가 정하고 비밀번호 관리자(예: macOS 암호 앱)에만** 저장합니다. 채팅·문서·저장소에 적지 않습니다.
- 운영 DB 연결 문자열(비밀번호 포함)과 Storage용 secret 키는 실행할 때 `read -s`로 입력하고, 끝나면 `unset` 합니다. Streamlit 설정에 다시 넣지 않습니다.
- 암호를 잃으면 복구할 수 없습니다.

## 5. 순서 (승인 후)
1. 이 Mac에 PostgreSQL 클라이언트 17 이상 설치(Postgres.app 또는 `brew install libpq`) — 운영 DB 버전 이상이어야 함
2. 운영자: 연습용 프로젝트 만들기, 백업 암호 정하기
3. 운영 DB 백업(운영자가 연결 문자열 입력) → `manifest.txt`의 표별 행 수 확인
4. 연습용 프로젝트에 복구(`TARGET_DB_URL`은 연습용 주소, 운영 주소는 스크립트가 거부)
5. 행 수 비교, 계정-사건 연결, 정책(본인만 조회) 확인 — 연습용 프로젝트에서 읽기만
6. (선택) 증거파일 백업·연습용 프로젝트로 올리기 확인
7. 연습용 프로젝트 삭제, 결과를 `docs/launch-status.md`에 기록

## 6. 삭제 계획
| 무엇 | 언제 | 방법 |
|---|---|---|
| 연습용 프로젝트(복구된 자료 포함) | 연습 당일 확인 직후 | Supabase 대시보드에서 프로젝트 삭제 |
| 풀린 임시 파일 | 스크립트가 끝날 때 자동 | `trap`으로 삭제 |
| 암호화된 백업 파일 | 정기 백업을 시작하면 '최근 4주분'만 두고 오래된 것부터 삭제. 시작하지 않으면 연습 후 바로 삭제 | Finder 휴지통 비우기 또는 `rm` |
| 탈퇴한 이용자 자료 | 백업 안에는 보관 기간 동안 남음 → 방침에 백업 보관 기간을 적어야 함(v3 검토 항목) | 보관 기간이 지나면 백업째 삭제 |

## 7. 운영자가 정할 것
- 연습 날짜, 백업 암호, 정기 백업 시작 여부(추천: 주 1회, 최근 4주 보관), 증거파일도 백업할지
