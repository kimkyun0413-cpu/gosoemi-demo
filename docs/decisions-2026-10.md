## 1. 메일 서비스 (인증 메일 시간당 2통 제한 해소)

### 현재
Supabase 기본 메일: 시간당 2통, 전달 보장 없음(Supabase 문서). 비밀번호 재설정 템플릿도 직접 SMTP가 있어야 고칠 수 있음.

### 핵심 조건: **내 도메인이 필요합니다**
- Resend는 "검증된 도메인"이 있어야 Supabase SMTP로 보낼 수 있다고 안내(Resend 문서).
- Gmail·Yahoo 발신 요건 때문에 gmail.com 같은 무료 메일 주소로는 도메인 인증을 할 수 없음(Brevo 도움말, 검색 결과로 확인 — 브라우저로 직접 열람은 차단됨).
- 지금 앱 주소(`*.streamlit.app`)는 내 도메인이 아니므로 **도메인 구입(연 단위 비용, 등록업체마다 가격 다름)이 먼저**입니다.

### 후보 비교 (공식 페이지 확인분만)
| 서비스 | 무료 한도 | SMTP | 도메인 | 비고 |
|---|---|---|---|---|
| **Resend** | 월 3,000통, **일 100통**, 도메인 3개 | 있음 (`smtp.resend.com:465`, 사용자 `resend`, 비밀번호=API 키) | 필수 | Supabase SMTP 연동 안내 문서가 있음 |
| Brevo | 일 300통(공식 소개 페이지 검색 결과) | 있음 | 사실상 필요(무료 주소는 인증 불가) | 무료 메일 표시(로고) 여부는 직접 확인 못 함 |
| AWS SES·Postmark·SendGrid·ZeptoMail | Supabase 문서의 예시 목록에 있음 | — | — | 무료 조건 미확인 |

### 추천: **도메인 구입 + Resend 무료**
- 이유: 무료 조건(월 3,000·일 100)을 공식 페이지에서 확인했고, Supabase 연동 절차가 문서로 정리되어 있음. 출시 초기 가입 규모에는 일 100통이면 지금(시간당 2통 = 하루 최대 48통)의 2배 이상.
- 하루 100통을 넘기 시작하면 Brevo(일 300) 또는 유료 전환을 검토.
- 비용: 도메인 비용만(Resend 무료 플랜).

### 필요한 정보
- 구입할 도메인 이름(예: 서비스명 기반), 보낸 사람 이름(예: 고소음이), 보낸 사람 주소(예: no-reply@도메인)

### 설정 순서
1. 도메인 구입 (운영자)
2. Resend 가입 → 도메인 추가 → 안내된 DNS 레코드(SPF·DKIM)를 도메인 관리 화면에 입력 → 검증 완료 확인 (운영자, Claude가 화면 안내 가능)
3. Resend에서 API 키 생성 (운영자, 키는 Supabase 화면에만 붙여 넣기)
4. Supabase > Authentication > Emails > SMTP Settings: 직접 SMTP 켜기, 위 값 입력 (운영자 또는 승인 후 Claude)
5. 직접 SMTP는 처음 시간당 30통 제한이 걸림(Supabase 문서) → Rate Limits에서 필요한 값으로 조정
6. 재설정 템플릿 링크를 `{{ .SiteURL }}?token_hash={{ .TokenHash }}&type=recovery`로 → Streamlit `PASSWORD_RESET_ENABLED = "true"` → 테스트 계정으로 재설정 시험
7. 개인정보처리방침에 메일 발송 위탁(Resend) 추가 — v3 검토 범위에 포함

**답해 주실 것:** 도메인을 살지(비용 발생), 산다면 원하는 도메인 이름

## 2. 백업 (Free 유지)

### 사실
- Free 플랜은 자동 백업 없음. Supabase는 Free 이용자에게 정기적으로 직접 내보내기를 권장(공식 문서).
- DB 백업에는 증거파일(Storage)이 들어가지 않음 → 따로 받아야 함.
- 1주일 동안 활동이 적으면 프로젝트가 일시 정지되고, 정지 후 1년 안에 대시보드에서 되살릴 수 있음(공식 문서).

### 준비한 방법 (실행하지 않음)
| 대상 | 도구 | 특징 |
|---|---|---|
| DB(회원·사건·초안·동의) | `scripts/backup_supabase.sh` | Docker 없이 PostgreSQL 클라이언트(pg_dump) 사용, 서버·클라이언트 버전 확인, 결과를 AES-256 암호화해 **이 컴퓨터에만** 저장 |
| 증거파일 | `scripts/backup_storage.py backup` | secret 키로 전체 목록을 100개씩 읽어 내려받고 암호화 |
| 복구 | `scripts/restore_supabase.sh`, `backup_storage.py restore` | **새 Supabase 프로젝트**에만 복구(운영 주소면 거부). Free는 프로젝트 2개까지 가능하므로 복구 연습도 무료 |

시험: 스크립트 문법 검사, 암호화·복호화 왕복(틀린 암호 거부), 파일 목록 읽기 단위 테스트. **실제 운영 DB 백업은 실행하지 않음**(이 Mac에 pg_dump 없음, 사용자 자료 복사 금지).

### 백업을 시작하면 함께 정해야 할 것
- 백업 파일에도 탈퇴한 이용자 자료가 남으므로 **보관 기간**(예: 최근 4주분만 유지 후 삭제)을 정하고 개인정보처리방침에 적어야 함
- 백업 암호 보관 방법(잃어버리면 복구 불가)
- 주기(예: 주 1회) — 활동이 거의 없을 때는 프로젝트 정지도 막는 효과는 없음(정지는 DB 요청 기준)

### 추천
- 출시 전 1회 복구 연습: 새 무료 프로젝트에 백업을 복구해 앱이 동작하는지 확인
- 이후 주 1회 백업, 최근 4주분 보관(검토 후 확정)

**답해 주실 것:** 백업을 시작할지, 시작한다면 주기와 보관 기간

## 3. 로그인 제한

### 실제 요청 구조 (코드 확인)
| 동작 | Supabase Auth 요청 | IP별 제한 |
|---|---|---|
| 이메일 로그인 | sign-in 1회 | 로그인·가입 5분 30회 |
| 가입 | sign-up 1회 | 같은 묶음 |
| 페이지 새로고침(로그인 유지 복원) | 토큰 갱신 1회 | 토큰 갱신 5분 150회 |
| 1시간마다 | 토큰 갱신 1회 | 같은 묶음 |
| 네이버·Google 로그인 완료 | 인증 확인 1회 | 인증 확인 5분 30회 |
| **(고치기 전) 화면을 다시 그릴 때마다** | 사건 수만큼 `/user` 호출 | 묶음 밖이지만 Auth 부하 |

모든 요청이 Streamlit 서버 한 곳에서 나가므로 IP별 제한을 이용자 전체가 나눠 씀.

### 이번에 고친 것 (완료)
- 파일 저장소 접근 때 생기던 `/user` 호출 제거: 사건 3건 기준 **화면 1회당 3회 → 0회**(사건이 늘수록 줄어드는 양이 커짐). 권한 판단은 그대로 Supabase가 토큰으로 함.

### 남은 개선안
| 안 | 효과 | 필요한 것 | 위험 |
|---|---|---|---|
| **A. IP 전달 켜기 (추천)** | 이용자마다 제한이 따로 적용 | ① Streamlit Secrets에 `SUPABASE_SECRET_KEY`, `AUTH_IP_FORWARDING_ENABLED="true"` ② Supabase Rate Limits에서 IP Address Forwarding 켜기 ③ 관리자 진단에서 "이용자 공인 IP 감지: 됨" 확인 | secret 키가 앱 서버에 추가됨(코드는 Auth 요청에만 사용, DB에는 쓰지 않음). Streamlit Cloud가 이용자 IP를 넘기지 않으면 효과 없음 → ③으로 먼저 확인 |
| B. 제한값 올리기 | 즉시 여유 | Supabase Rate Limits 수정 | 공격 시 막는 힘이 약해짐 |
| C. 그대로 두기 | — | — | 동시 접속이 늘면 로그인·새로고침 실패 |

**추천 순서:** 관리자 진단으로 IP 감지 확인(`ADMIN_EMAILS` 설정 필요) → 감지되면 A, 안 되면 B를 소폭.
**답해 주실 것:** A를 위해 secret 키를 Streamlit 설정에 추가해도 되는지

## 4. 결제

### 결제사 후보 (공식 문서 확인분)
| 후보 | 성격 | 확인한 사실 |
|---|---|---|
| 토스페이먼츠 | PG(직접 계약) | 회원가입(이메일·전화번호)만으로 **사업자 없이 테스트 키** 사용 가능, 테스트는 실제 출금 없음. **자동결제(빌링)는 리스크 검토와 추가 계약 후 사용** |
| 포트원 | 여러 PG를 한 규격으로 연결하는 연동 서비스(PG 아님) | 관리자 가입은 무료, **PG 가맹 계약은 따로 필요**. 정기결제는 실운영 MID 발급 후 PG 쪽 설정 필요 |
| Stripe | — | 한국은 지원 국가 목록에 없음(사용 불가) |

### 구현 준비 상태
| 항목 | 건당 결제 | 월 구독 |
|---|---|---|
| DB 구조(주문·중복 방지·금액 확인·이용권) | 준비됨(로컬 30/30) | 준비됨: 갱신 실패→past_due, 해지→기간 끝까지, 만료 |
| 결제 결과 서버 확인(웹훅) | 공통 구조 준비(가짜 결제사 8/8) | 같음 |
| 결제사 연동(어댑터) | 결제사 결정 후 작성 | 같음 |
| 결제 화면 | 결제사 결정 후 | 같음 |
| 빌링키 발급·안전 보관(Vault 등) | 해당 없음 | **미구현** |
| 매월 자동 청구 예약 작업 | 해당 없음 | **미구현**(Supabase 예약 작업 등) |
| 환불 처리 | 이용권 종료까지 준비 | 같음 |
| 법적 준비 | 사업자등록, 통신판매업 신고(전자상거래법 제12조), 청약철회 안내(제17조), 결제 기록 5년 보존(시행령 제6조) | 같음 + 자동결제 추가 계약·심사 |

### 계약에 필요한 정보 (토스페이먼츠 기준 확인분 + 일반)
- 개인사업자: 사업자등록증, 대표자 휴대폰 본인인증. 통신판매업 신고증은 신청 후 제출 가능(PortOne 도움말의 토스페이먼츠 계약 절차)
- 서비스 설명, 평균 결제 금액, 월 예상 거래량(자동결제 심사 시)
- 사이트 주소, 상품·가격·환불 안내 페이지, 이용약관, 정산 계좌

### 추천 진행 순서 (가격·업체 미확정)
1. 판매 상품과 가격 범위 결정(건당 / 월 구독 / 둘 다)
2. 사업자등록 → 통신판매업 신고
3. 결제사 선택: 한 곳만 쓸 계획이면 PG 직접 계약, 나중에 여러 곳을 붙일 계획이면 포트원 + PG
4. 테스트 키로 건당 결제부터 연동·시험 → 구독은 자동결제 계약 후

**답해 주실 것:** 유료화를 할지, 한다면 건당·구독 중 무엇부터, 사업자등록 계획

## 5. 실제 음성 테스트 (공개 기능은 끈 채로)

### 추천: 관리자 시험 모드 (완료, 꺼져 있음)
- Streamlit Secrets에 `ADMIN_EMAILS = "운영자 이메일"`만 추가하면 그 계정에만 음성 입력과 운영자 진단이 보임. 일반 이용자에게는 보이지 않음.
- 운영 AI 키는 서버에만 있고 화면·로그에 나오지 않음(진단에도 '설정됨/없음'만 표시).
- 시험 음성: 개인정보 없는 합성 음성 `tests/fixtures/voice_test_ko.wav`(“시험용 음성입니다. 9월 2일 … 45만 원 … 판매왕 …”). PC에서 '음성파일 올리기'로 올리거나, 휴대폰으로 같은 문장을 읽어 녹음.
- 확인할 것: 받아쓰기 정확도, 입력칸 정리, "(확인 필요)" 표시, 덮어쓰기 경고, 초안 생성, 실패 안내

### 대안: 이 컴퓨터에서 스크립트로 (운영 키를 쓰지 않는 방법)
- `scripts/voice_smoke_test.py`: 키를 `read -s`로 입력(화면에 안 보임), 출력·저장하지 않음
- 운영 키 대신 **별도 시험용 키**를 쓰는 것을 권장. 단, Google의 무료(Unpaid) 이용분은 입력이 제품 개선에 쓰일 수 있으므로(Gemini API 추가 약관) 합성 음성만 사용

**답해 주실 것:** 관리자 시험 모드에 쓸 운영자 이메일
