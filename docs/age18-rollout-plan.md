# 만 18세 이용 기준 — 전문가 검토 자료와 운영 적용 순서 (한 문서)

**결정 (2026-10-13, 운영자):** 고소미의 이용 기준을 **만 18세 이상**으로 정함.
**지금 상태:** 화면·약관·방침·DB 수정안 준비와 검사까지 완료. **운영에는 아무것도 적용하지 않음** — 운영 가입 연령(만 14세)·약관(2026-09-15)·방침(2026-09-27)·DB 그대로. AI 멈춤(`AI_FEATURES_PAUSED`), 이메일 신규 가입 중단(`EMAIL_SIGNUP_ENABLED=false`), 결제 보류 유지.
**시행일:** 아직 정하지 않음(전문가 검토 후 운영자가 정함).

**왜:** 고소미의 AI 기능(상담·초안·음성)은 Google Gemini API를 씁니다. Gemini API 추가 약관과 Google Cloud(Vertex AI) 약관 모두 "18세 이상만 이용, 18세 미만이 대상이거나 이용할 가능성이 높은 서비스에서 사용 금지"라고 정합니다([Gemini API 추가 약관](https://ai.google.dev/gemini-api/terms)).

## 2. 약관·방침 수정안 (화면과 일치하도록 맞춤)

**이용약관 제4조(이용 자격)** — 만 18세 설정일 때만 바뀌고, 나머지 조항은 2026-09-15 시행본과 같습니다.
> 서비스는 만 18세 이상만 이용할 수 있습니다. 서비스의 AI 기능에 쓰는 Google Gemini API의 이용 조건(18세 이상, 18세 미만이 이용할 서비스에서 사용 금지)에 따른 것입니다. 만 18세 미만인 경우 회원가입 및 서비스 이용이 제한됩니다.
> 이 기준을 시행하기 전에 가입한 이용자는 다음 이용 때 만 18세 이상인지 다시 확인합니다. 확인하지 않으면 서비스를 이용할 수 없으며, 이때에도 운영자는 계정과 저장한 자료를 임의로 삭제하지 않습니다. 이용자는 로그인해 저장한 자료를 내려받을 수 있고, 언제든지 직접 탈퇴해 모두 삭제할 수 있습니다.

**개인정보처리방침 v3 수정안**(`policy_text.py`, `min_age=18`) — 이번에 바꾼 곳:
- 9절 이용 연령: 만 18세 + 이유 + "만 18세 미만이거나 바뀐 약관에 동의하지 않은 경우에도 계정·자료를 임의로 삭제하지 않으며, 로그인해 내려받거나 직접 탈퇴할 수 있음"
- 8절 권리 행사: '내 자료 모두 내려받기'(ZIP) 추가, 이용할 수 없게 된 경우에도 내려받기·탈퇴 가능
- 1절 처리 항목: "만 18세 이상 확인 여부와 확인 일시" → "확인 여부, Google·네이버 로그인으로 처음 이용할 때의 연령 확인 일시". 이유: 운영 `consent_records`에 동의 시각 열이 있는지 확인되지 않음(2026-10-13 내려받기 오류에서 `created_at`이 없는 것으로 보임). 기록하지 않을 수 있는 일시를 방침에 적지 않음
- 변경 전·후 비교표(시행 전 안내 화면)도 같이 고침
- 전문 확인: [privacy-review-packet.md](privacy-review-packet.md) 6절(만 18세 기준으로 생성), 약관은 앱의 '이용약관 보기'(18세 설정 시)

**알아 둘 점:** Google 첫 확인 시각은 계속 `age_14_confirmed_at`이라는 이름의 칸에 저장됩니다(이름만 옛것, 18세 설정에서는 18세 확인 시각). 이용 허용은 새 약관 동의로만 판단합니다.

## 3. 기존 계정·자료 처리와 보관 기간 (정하지 않음)
- **자동 삭제하지 않음.** 18세 미만이라고 하거나 동의하지 않은 계정도, 아무 응답이 없는 계정도 운영자가 지우지 않습니다. 앱·DB 어디에도 자동 삭제 코드가 없습니다.
- 이용자 스스로: 로그인 → 내려받기 → 회원탈퇴. 문의 이메일로 요청하면 운영자가 처리(방침 '정보주체의 권리').
- **보관 기간은 미정.** 지금 문구는 "이용자가 탈퇴할 때까지"와 같은 뜻입니다. 기간을 정하면 약관·방침·제한 화면 문구를 바꾸고 다시 검사해야 합니다.

| 정할 것 | 선택지 | 비고 |
|---|---|---|
| 미충족·거부 계정의 보관 | (가) 탈퇴할 때까지(지금 문구) (나) 안내 후 일정 기간(예: 30일) 뒤 삭제 | (나)는 삭제 기능·안내 메일이 새로 필요(메일 서버 없음) |
| 장기 미이용 계정 | 기준 없음 / 예: 1년 미접속 시 안내 후 삭제 | 메일 안내 수단 필요 |
| 탈퇴 후 동의 기록 | 지금: 탈퇴 때 함께 삭제(`delete-account` 함수) | 남기려면 배포된 함수 수정 + 방침에 기간 |
| 이미 처리된 14~17세 자료 | 그대로 | 전문가 확인 |

## 4. 전문가 검토 요청

**건네드릴 자료:** 이 문서, [privacy-review-packet.md](privacy-review-packet.md)(질문 14개 + v3 전문, 만 18세 기준), 위 2절의 약관 조항.

**만 18세 관련 질문** (검토 자료 질문 13에 같은 내용, 질문 7·14도 관련)
1. 나이를 **본인 체크(자기 신고)** 로만 받는 방식으로 충분한지
2. 미충족·거부 계정의 계정·자료를 언제까지 둘지 — 기한 없이 두는 것이 최소 보관 원칙에 맞는지, 기간을 둔다면 며칠·어떤 안내가 필요한지
3. 이미 처리한 14~17세 이용자 자료에 대해 할 일이 있는지(이용자 안내 등)
4. 이 변경을 이용자에게 불리한 약관 변경으로 보아 **사전 안내를 30일** 두어야 하는지(7일로 충분한지)
5. 거부 시 이용을 막고 내려받기·탈퇴만 허용하는 방식이 약관 변경 절차로 적절한지
6. 탈퇴 후 동의(연령 확인) 기록을 남겨야 하는지, 남긴다면 기간
7. (질문 14) AI를 멈추기 전 무료 등급으로 처리된 내용에 대한 조치, 유료 전환 후 문구

## 5. 운영 적용 순서

**A. 준비 (운영 변화 없음)**
1. 전문가 검토(4절) → 결과에 따라 Claude가 약관·방침·화면 문구 수정, 다시 검사
2. 운영자 결정: 시행일(약관 v2와 방침 v3 **같은 날** 추천), 사전 안내 기간(전문가 의견), 보관 기간(3절)
3. (Claude, 읽기만) 운영 `consent_records` 열 구성 확인 — 동의 시각 열이 있으면 방침에 '동의 일시'를 다시 넣을 수 있음. 이용자 행은 읽지 않음

**B. 사전 안내 시작일** (Streamlit 설정 2줄, 운영자 승인 후)
4. `TERMS_V2_UPCOMING_DATE = "시행일"`, `PRIVACY_POLICY_UPCOMING_DATE = "시행일"` → 앱 위쪽에 약관·방침 변경 안내 두 개가 보임
5. **DB 전환 함수 적용**(운영자 승인 후, 언제 해도 지금 앱에 영향 없음): `supabase/proposals/age18/record_consent_terms_v2_transition.sql`의 `__TERMS_V2_DATE__`, `__PRIVACY_V3_DATE__`를 시행일로 바꿔 실행 → 옛·새 버전 동의를 모두 받음. 실행 전 사전 점검(`supabase/checks/`), 실행 후 시험 계정으로 지금 앱 동의 저장 확인

**C. 시행일** (이용자가 적은 시간)
6. Streamlit 설정: `MIN_USER_AGE = "18"`, `TERMS_EFFECTIVE_DATE_V2 = "시행일"`, `PRIVACY_POLICY_EFFECTIVE_DATE = "시행일"`. 4번의 두 줄은 지워도 되고 남겨도 저절로 사라짐
   - 5번 전환 함수를 미리 적용했으므로 앱과 DB가 받는 버전이 어긋나는 시간이 없음(로컬 시험으로 확인)
7. 확인(시험 계정 A·B): 동의 화면에 18세 체크 → 동의 기록이 새 버전으로 남는지, '만 18세 미만입니다'·'동의하지 않습니다' → 이용 제한 화면에서 내려받기, (B 계정으로만) 탈퇴 화면이 열리는지까지
8. (선택, 며칠 뒤) `record_consent_terms_v2.sql`로 새 버전만 받게 좁히기

**지금 그대로 둘 것:** AI 멈춤, 이메일 신규 가입 중단, 결제 보류. 18세 적용과 별개로 따로 결정합니다.

## 6. 되돌리는 방법
1. Streamlit 설정에서 `MIN_USER_AGE`, `TERMS_EFFECTIVE_DATE_V2` 두 줄 삭제 → 만 14세·옛 약관(2026-09-15)으로 돌아감. v3도 되돌리려면 `PRIVACY_POLICY_EFFECTIVE_DATE = "2026-09-27"`
2. Supabase SQL: `supabase/proposals/age18/record_consent_terms_v2_rollback.sql` → 동의 함수가 옛 버전(방침 2026-09-27·2026-10-13)을 받음
- 되돌려도 지워지는 것은 없습니다. 새 버전 동의 기록은 남고, 제한됐던 계정도 다시 이용할 수 있습니다.
