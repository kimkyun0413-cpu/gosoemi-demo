# 만 18세 이용 기준 적용안 (2026-10-12 정리, 운영 미적용)

**왜:** 고소미의 AI 기능(상담·초안·음성)은 Google Gemini API를 씁니다. Gemini API 추가 약관과 Google Cloud(Vertex AI) 약관 모두
"18세 이상만 이용, 18세 미만이 대상이거나 이용할 가능성이 높은 서비스에서 사용 금지"라고 정합니다. 지금 고소미는 만 14세 이상 가입을 받습니다.

**현재 상태:** 화면·약관·방침·DB 수정안은 준비되어 있고(코드는 설정을 켜기 전에는 지금과 같음), 운영에는 적용하지 않았습니다.
운영은 지금 AI 기능을 멈춘 상태(`AI_FEATURES_PAUSED`)이고, 새 이메일 가입도 멈춘 상태(`EMAIL_SIGNUP_ENABLED=false`)입니다.

---

## 1. 새 이용자의 가입 방식
| 가입 방법 | 화면 | 기록 |
|---|---|---|
| 이메일(지금은 멈춤) | 가입 양식의 필수 체크가 "만 18세 이상입니다"로 바뀜 | 가입 뒤 첫 로그인 때 아래 동의 화면을 한 번 더 거침 |
| Google·네이버 | 처음 로그인 때 나이 확인 문구가 "만 18세 이상"으로 바뀜 | 이어서 동의 화면 |
| 공통: 동의 화면 | 새 약관·방침 전문 + 필수 체크 3개: 이용약관 동의, 개인정보 수집·이용 동의, **만 18세 이상입니다** | 새 약관 버전(시행일)에 동의한 기록이 `consent_records`에 남음 → 이것이 18세 이상 확인 기록 |
- DB에 새 칸을 만들지 않습니다. '만 18세 이상 확인이 들어간 새 약관 버전'에 동의한 기록을 확인 기록으로 씁니다.
- 참고: Google·네이버 첫 확인은 기존 저장 위치(Google 계정 정보의 `age_14_confirmed_at`, 네이버 연결 표)에 그대로 남지만, 이용 허용 여부는 새 약관 동의(18세 확인 포함)로 판단합니다.

## 2. 기존 이용자의 나이 재확인 방식
- 새 약관 버전이 시행되면, 기존 이용자는 **다음 로그인 때 자동으로 동의 화면**을 봅니다(지금도 약관·방침이 바뀌면 다시 묻는 구조).
- 동의 화면에서 "만 18세 이상입니다"에 체크하고 동의 → 평소처럼 이용.
- "만 18세 미만입니다"를 누르면 → 이용 제한 안내 화면(아래 3).
- 체크 없이 넘어갈 수 없고, 옛 약관 동의로는 이용할 수 없습니다(앱이 새 버전 동의만 확인, DB 함수도 새 버전만 받음).
- 미리 알리기: 시행일 전에 앱 위쪽에 바뀌는 내용을 알리는 기능이 이미 있습니다(`PRIVACY_POLICY_UPCOMING_DATE`).

## 3. 18세 미만 이용자: 자료 내려받기와 탈퇴
### 지금 준비된 것
- 안내 화면: "만 18세 이상만 이용할 수 있어요", 계정과 자료는 **운영자가 임의로 지우지 않음**, 문의 이메일
- 버튼: '다시 확인하기'(잘못 누른 경우), '로그아웃', **'회원탈퇴'**(지울 내용을 한 번 더 보여 주고 계정·사건·초안·증거파일을 모두 삭제)

### 내 자료 모두 내려받기 — 2026-10-12 구현 완료
- '내 계정' 화면과 18세 미만 안내 화면에 **'내 자료 모두 내려받기'** 버튼: 사건 내용·저장된 초안·사건 정리(경위·증거 설명·일정·체크리스트)·증거파일·동의 기록을 사건별 폴더로 정리한 ZIP
- 저장하지 않는 AI 대화는 포함되지 않는다고 안내, 로그인 토큰·비밀번호·인증키 제외, 본인 자료만(다시 한 번 거름)
- 일부를 받지 못하면 '받지 못한 자료' 목록을 화면과 파일에 표시(다 담았다고 하지 않음). 증거파일이 많으면 약 40MB씩 나눠 받기, 전체 약 200MB를 넘는 파일은 사건 화면에서 하나씩 받도록 안내
- AI·DB 변경 없음. 자동 테스트(가상 자료)·로컬 브라우저(PC·휴대폰 크기)로 확인, 운영 앱에서 내려받기·동의 기록 파일은 운영자 확인(2026-10-13). 증거파일 포함은 미확인(시험 계정에 증거파일 0개)

### 문의로 요청하는 경우
- 문의 이메일로 삭제·열람을 요청하면 운영자가 처리(방침 '정보주체의 권리'). 본인 확인 방법을 정해 두는 것이 좋습니다(가입 이메일로 답장 받기 등).

## 4. 자료 보관 기간 — 운영자가 정할 것
| 항목 | 지금 수정안 | 정할 것(추천) |
|---|---|---|
| '18세 미만'이라고 한 이용자의 계정·자료 | 이용자가 직접 탈퇴할 때까지 보관(이용은 막힘) | 기한 없이 두는 것은 최소 보관 원칙과 맞지 않을 수 있음. **추천: 안내 후 일정 기간(예: 30일) 뒤 삭제**, 그 전에 내려받기 안내. 기간은 전문가 확인 |
| 아무 응답 없이 다시 오지 않는 기존 이용자 | 별도 규칙 없음(회원탈퇴 때까지) | 장기 미이용 계정 처리 기준을 둘지(예: 1년 미접속 시 안내 후 삭제) |
| 동의 기록(`consent_records`) | 회원탈퇴 때 계정·사건과 함께 삭제됨(`delete-account` 함수 확인) | 동의 증빙을 탈퇴 후에도 남길지(남기면 방침에 기간 명시, 바꾸려면 배포된 함수 수정 필요) |
| 백업 파일 | 백업 시작 시 최근 4주분(안) | 삭제를 요청한 이용자의 자료가 백업에 남는 기간을 방침에 적기 |
| 이미 처리된 14~17세 이용자 자료 | 그대로 | 전문가 확인(검토 자료 질문 13) |
- 위 결정은 방침(v3) 문구에 반영해야 합니다. 정해 주시면 문구와 화면을 고치겠습니다.

## 5. 적용 순서
**준비(운영 변화 없음)**
1. 전문가 검토: 약관·방침 수정안, 위 4번 보관 기간, 기존 14~17세 처리(검토 자료 `docs/privacy-review-packet.md` 질문 13·14)
2. 결정: 새 약관 시행일, 방침 v3 시행일(같은 날 추천), 사전 안내 기간(흔히 7일, 이용자에게 불리한 변경은 30일을 두는 경우가 많음 — 전문가와 확정)
3. (추천) '내 자료 모두 내려받기' 구현·시험
4. 로컬 시험 다시 실행: `supabase/tests/local_age18_consent_test.py`, 앱 자동 테스트

**사전 안내 시작일**
5. Streamlit 설정 `PRIVACY_POLICY_UPCOMING_DATE = "시행일"` → 앱 위쪽에 바뀌는 내용 안내(약관 안내 문구도 함께 넣을지 결정)

**시행일 (이용자가 적은 시간, 10분 안에 연달아)**
6. Supabase SQL: `supabase/proposals/age18/record_consent_terms_v2.sql`의 `__TERMS_V2_DATE__`, `__PRIVACY_V3_DATE__`를 날짜로 바꿔 실행(운영자 승인 후, 실행 전 사전 점검)
7. Streamlit 설정: `MIN_USER_AGE = "18"`, `TERMS_EFFECTIVE_DATE_V2 = "시행일"`, `PRIVACY_POLICY_EFFECTIVE_DATE = "v3 시행일"`(v3 시행과 함께라면)
   - 6과 7 사이 몇 분 동안은 동의 저장이 실패할 수 있음(앱과 DB가 받는 버전이 다름). 원하면 '옛·새 버전 모두 받는' 전환용 SQL을 따로 준비할 수 있음
8. 확인: 시험 계정 A·B로 로그인 → 동의 화면에 18세 체크, '만 18세 미만입니다' 화면, 새 가입 화면 문구, 동의 기록이 새 버전으로 남는지

## 6. 되돌리는 방법
1. Streamlit 설정에서 `MIN_USER_AGE`, `TERMS_EFFECTIVE_DATE_V2` 두 줄 삭제 → 앱이 만 14세·옛 약관(2026-09-15)으로 돌아감
2. Supabase SQL: `supabase/proposals/age18/record_consent_terms_v2_rollback.sql` 실행 → 동의 함수가 옛 버전을 다시 받음
3. 방침 v3를 이미 시행했다면 그대로 두어도 됨(앱이 만 14세 문구로 보여 줌). v3도 되돌리려면 `PRIVACY_POLICY_EFFECTIVE_DATE`를 2026-09-27로
- 되돌려도 지워지는 것은 없습니다: 새 버전 동의 기록은 남고, '18세 미만'이라고 한 이용자의 계정·자료도 그대로라 다시 이용할 수 있습니다.
- 로컬 시험으로 되돌리기까지 확인함(10/10)
