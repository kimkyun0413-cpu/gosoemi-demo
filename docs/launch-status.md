## 운영 상태
- 운영 DB 적용 완료: `case_drafts` 테이블(①), 계정 간 차단 테스트(③) 통과. 기록: [2026-10-case-drafts-rollout.md](2026-10-case-drafts-rollout.md)
- 적용 안 함: ② 동의 함수 변경, 방침 사전 안내, v3 시행, 초안 저장 활성화(`DRAFT_SAVE_ENABLED`), 음성 입력 활성화(`VOICE_INPUT_ENABLED`)
- 음성 입력: 코드 완료, 꺼져 있음. v3 시행 후 켜고 운영 앱에서 실제 녹음으로 확인 필요(이 Mac에는 Gemini 키가 없어 실제 받아쓰기는 시험하지 못함)
- 테스트 계정 A(`53bf9e60-…`), B(`088bd25e-…`)는 시행 후 확인에 쓰므로 유지

## 출시를 막는 문제
| # | 문제 | 확인 근거 | 해결 방법 | 필요한 결정 |
|---|---|---|---|---|
| 1 | 인증 메일이 프로젝트 전체에서 **시간당 2통**만 발송됨 → 가입자가 몰리면 인증 메일이 안 감 | Supabase Auth > Rate Limits (기본 메일 사용 중, 직접 SMTP 꺼짐) | 직접 메일 서버(SMTP) 연결 | 메일 발송 서비스 선택(무료 한도가 있는 서비스도 있음, 비용 여부 확인) |
| 2 | 비밀번호 재설정 불가 | 직접 SMTP가 없으면 메일 템플릿을 고칠 수 없음(대시보드 안내). 앱은 `token_hash` 방식 링크가 필요 | SMTP 연결 → 재설정 템플릿 링크를 `{{ .SiteURL }}?token_hash={{ .TokenHash }}&type=recovery`로 → Streamlit에 `PASSWORD_RESET_ENABLED = "true"` | 1번과 같이 |
| 3 | 현재 시행 중인 방침(v2)에 파기 절차, 자동 수집 장치, 서비스 호스팅(Streamlit) 위탁, 국외 이전 기재사항 일부가 없음 | 개인정보 보호법 제28조의8·제30조와 대조 | v3 검토·시행 | 전문가 검토, 시행일 |
| 4 | 로그인·토큰 갱신이 Streamlit 서버 한 곳의 IP에서 나가므로 IP당 제한(로그인·가입 5분 30회, 토큰 갱신 5분 150회)을 모든 이용자가 나눠 씀 | Supabase Auth > Rate Limits | 대시보드에서 제한값 상향 검토(설정 변경) | 상향 여부 승인 |
| 5 | DB 백업 없음(Free) → 장애 시 사건 복구 불가 | Database > Backups | 유료 플랜 또는 정기 내보내기 | 비용 결정(이번에는 Free 유지) |

## 출시 전 정리하면 좋은 것
- Supabase Redirect URLs의 `http://localhost:8501` 삭제(운영에는 불필요)
- AI 사용 제한은 서버 메모리 기준(계정당 시간 30회, 전체 시간 300회). 앱 재시작 시 초기화되고, 앱 서버가 여러 대가 되면 서버마다 따로 셈 → Google Cloud에서 Gemini API 사용량 한도·예산 알림 설정 권장
- 한글 증거파일 이름이 저장소 규칙 때문에 "evidence.jpg"처럼 보임
- 결제: [billing-readiness.md](billing-readiness.md) — 사업자등록·통신판매업 신고·결제사 결정 전에는 판매 불가

1. 검토 결과 받으면 v3 문구 수정 → 시행일 확정 → ② SQL 날짜 수정·실행 → 사전 안내 설정 → 시행일에 시행·초안 저장 활성화 ([privacy-policy-v3-review.md](privacy-policy-v3-review.md) 5절)
2. SMTP 연결 후 비밀번호 재설정 켜고 운영 앱에서 재설정 메일 시험
3. 결제사·사업자 정보가 정해지면 결제 어댑터 작성과 테스트 키 시험
