## 새 AI 대화·음성 대화 (2026-10-10, 관리자 시험 모드에서만 보임)
- 화면: 'AI 상담' 탭. 관리자에게는 새 대화가, 일반 이용자에게는 기존 화면이 보임
- 글 대화: 같은 대화의 이전 질문·답변(최근 20개)을 함께 보내 후속 질문에 반영. 짧게 답하고 필요한 것을 하나씩 묻도록 지시. 새 대화·대화 지우기, 답변 중에는 입력창·버튼 잠금, 10초 안 같은 질문 중복 전송 방지, 실패 시 질문을 남겨 고쳐서 다시 보내기
- 음성 대화: '🎤 말로 질문하기' → 마이크를 누른 동안만 녹음 → 글로 바꾸기(기존 음성 인식 코드 재사용) → 글 확인·수정 → 보내기 → 글 답변 + 답변 듣기. 녹음은 글로 바꾼 직후 서버 업로드 저장소에서 삭제. 실시간(전화식) 대화는 추후 기능
- 답변 듣기: 브라우저 내장 음성(Web Speech API)에서 **기기 안 한국어 음성(`localService`)만** 사용 → 추가 비용·새 서비스·키 없음, 답변 글을 외부 음성 서버로 보내지 않음. 켜기·끄기, 재생·정지. 새 대화·로그아웃·새로고침 시 읽기 멈춤
  - 선택 이유: Gemini TTS(`gemini-3.8-flash-lite-tts`, 한국어 지원)는 오디오 출력 100만 토큰당 $6(2027-01-01부터 $12)이고 답변 글을 Google에 한 번 더 보냄. 브라우저 음성은 무료지만 일부 데스크톱 Chrome의 'Google 한국의' 같은 원격 음성은 글이 외부로 갈 수 있어 제외
  - 기기별 차이: macOS(이 Mac의 앱 내 브라우저)에서는 '유나' 등 기기 안 한국어 음성 9개 확인. Chrome은 페이지에서 사용자가 한 번 이상 누른 뒤에만 읽기를 허용(M71~), iPhone Safari는 더 엄격해 자동 재생이 막히면 '▶ 답변 듣기'를 누르라고 안내. 기기에 한국어 음성이 없으면(일부 Windows·Android) 듣기 불가 안내 후 글로 이용
- 사건 정보 정리: '📝 이 대화로 사건 정보 정리하기' → 이용자 발언만(AI 답변 제외) 기존 입력칸 정리 규칙으로 정리 → 항목별 체크·수정 → '고소장 작성' 탭 입력칸에 넣기. 이미 적은 칸은 기본 해제+경고, 사건 자동 저장 없음
- 법률 답변 원칙(지시문): 사실·추측 구분, 범죄 성립·승소·처벌 단정 금지, 확인 안 된 판례·법조문·기한 금지, 검색하지 않으므로 '최신 정보 확인' 표현 금지, 위험하면 112 먼저. 화면 상단에 AI 한계 한 줄 안내
- 대화 보관: DB 저장 없음. 서버 메모리에만 있고 새 대화·지우기·로그아웃·계정 변경 시 즉시 삭제. 새로고침·탭 닫기 시 화면에서 바로 사라지고, 서버 메모리는 연결이 끊긴 뒤 약 2분 뒤 정리(Streamlit `server.disconnectedSessionTTL` 기본 120초). Google 보관(55일 안내)은 앱이 지울 수 없음을 화면·방침에 구분해 적음
- 비용·제한(공식 가격표 기준, 유료 등급): 받아쓰기·답변·정리 모두 기존 `gemini-3.5-flash-lite`(입력 100만 토큰당 $0.30, 출력 $2.50). 음성은 1초에 32토큰(1분 ≈ 1,920토큰 ≈ $0.0006). 답변 1회는 대략 $0.001~0.002. 답변 듣기는 기기에서 처리해 비용 없음. 기존 계정당 1시간 30회·전체 300회 제한과 90초 시간 초과를 그대로 적용(음성 질문은 받아쓰기+답변 2회로 셈)
- 운영자 시험 절차: 관리자 계정(A)으로 로그인 → 'AI 상담' 탭 → ① 글로 2~3번 이어서 질문 ② '🎤 말로 질문하기'로 시험 문장 녹음(PC·휴대폰 각각) → 글 확인 후 보내기 → 답변 듣기·정지 ③ '이 대화로 사건 정보 정리하기' → 넣기 → '고소장 작성' 탭에서 확인(저장은 하지 않아도 됨) ④ 새 대화·대화 지우기 ⑤ 로그아웃 후 다시 로그인해 대화가 없는지 확인. 개인정보 없는 시험 내용만 사용

## 이용자 IP 신뢰성 (2026-10-06)
- 앱은 X-Forwarded-For를 오른쪽부터 읽도록 고침(왼쪽 값은 이용자가 써 넣을 수 있음)
- Streamlit Community Cloud 앞단 프록시가 이용자가 넣은 값을 지우는지에 대한 공식 문서는 찾지 못함(GitHub 이슈 #12005: `st.context.ip_address`는 프록시 뒤에서 실제 IP를 반영하지 않음)
- 결론: 신뢰 경로 미확인 → IP 전달 기능은 켜지 않음. 로그인 제한이 문제가 되면 우선 Supabase 제한값 소폭 상향을 검토
