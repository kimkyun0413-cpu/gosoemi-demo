## 실제 음성 시험 결과 (2026-10-10, 운영 앱 관리자 시험 모드)
- 관리자 시험 계정: 테스트 계정 A (Supabase 사용자 ID `53bf9e60-4bba-48c2-8ad3-8c6db3e8644c`). 관리자 판별은 `ADMIN_USER_IDS` + 서버에서 토큰 주인 확인
- 시험 음성: `tests/fixtures/voice_test_ko.wav`(합성, 개인정보 없음)
- 운영자가 확인한 결과:
  - 받아쓰기: 시험 문장 핵심어 5/5 인식
  - 입력칸 반영: 판매왕, 9월 2일, 45만 원, 채팅·이체 내역, 목격자 없음
  - 말하지 않은 본인 정보와 처벌 의사는 빈칸으로 남음(지어내지 않음)
  - ‘온라인 중고거래’는 장소 칸에 들어가지 않아 운영자가 직접 입력
  - 이후 초안 생성까지 완료
- 확인하지 않은 것: 생성된 초안 내용의 정확성(검토하지 않음), 실제 휴대폰 마이크 녹음
- 장소 칸 누락 원인(코드 기준 추정, 운영 키 없이 재현하지 못함): 입력칸 정리 지시문에 장소 칸 설명이 '사건 발생 장소'뿐이고 '장소를 만들지 말라'는 금지만 있어, AI가 '온라인 중고거래'를 거래 방식(사건 유형)으로 보고 장소로는 넣지 않은 것으로 보임
- 수정: 지시문에 "말한 장소는 그대로 장소 칸에 넣고, 온라인에서 일어났다고 말한 것도 장소다(예: '온라인 중고거래'). 말하지 않은 앱·사이트 이름은 덧붙이지 말 것" 규칙 추가. 자동 테스트 추가
- 다음: 배포 후 같은 시험 음성으로 장소 칸이 채워지는지 관리자 시험 모드로 재확인

## 이용자 IP 신뢰성 (2026-10-06)
- 앱은 X-Forwarded-For를 오른쪽부터 읽도록 고침(왼쪽 값은 이용자가 써 넣을 수 있음)
- Streamlit Community Cloud 앞단 프록시가 이용자가 넣은 값을 지우는지에 대한 공식 문서는 찾지 못함(GitHub 이슈 #12005: `st.context.ip_address`는 프록시 뒤에서 실제 IP를 반영하지 않음)
- 결론: 신뢰 경로 미확인 → IP 전달 기능은 켜지 않음. 로그인 제한이 문제가 되면 우선 Supabase 제한값 소폭 상향을 검토

## 실제로 확인한 것과 못 한 것
- 확인: 자동 테스트 63개, 실제 WAV 파일로 업로드 → (가짜 AI) 변환 → 수정 → 정리 → 덮어쓰기 경고 → 초안, 실제 Streamlit 서버에서 음성 삭제
- 로그인 관련: 화면 1회당 Auth 호출 3→0(가짜 서비스로 호출 수 측정), supabase 라이브러리가 헤더 토큰을 그대로 쓰는지 네트워크 차단 테스트
- 운영 앱(관리자 시험 모드, 운영자 확인): 실제 Gemini 음성 인식 → 입력칸 정리 → 초안 생성 (2026-10-10). 초안 내용의 정확성은 검증하지 않음
- 못 함: 장소 칸 수정 후 실제 Gemini 재확인, 실제 휴대폰 마이크 녹음, 결제사 연동
